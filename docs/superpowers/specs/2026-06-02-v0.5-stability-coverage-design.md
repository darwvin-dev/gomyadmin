# v0.5 Stability & Coverage Design

**Goal:** Bring all packages to ≥90% test coverage, surface and fix production bugs via integration-first testing, and refactor weak code — clearing the path to v1.0.

**Approach:** Integration tests first (real PostgreSQL, full stack), then unit coverage fill, then targeted refactors. Breaking API changes are allowed since we are pre-v1.0.

**Context:** This is sub-project A on the roadmap to v1.0 (Feature Complete). Subsequent versions add OAuth/API Key (v0.6), Dashboard (v0.7), React SDK (v0.8), Plugin System (v0.9), then v1.0 API lock.

---

## Architecture

Three sequential phases:

```
Phase 1 — Integration Foundation   (PostgreSQL required)
Phase 2 — Unit Coverage Fill       (no external deps)
Phase 3 — Bug Fix & Refactor       (triggered by Phases 1 & 2 findings)
```

Each phase feeds the next: integration tests expose real bugs → unit tests expose design problems → refactors fix root causes.

## Phase 1: Integration Foundation

### New files

**`tests/integration/server_integration_test.go`** (`//go:build integration`)
Full HTTP stack tests against a real PostgreSQL database:
- Complete Login → CRUD (List, Get, Create, Update, Delete) → Logout flow
- Bulk delete with deduplication
- File upload and download via local storage
- Audit log recording and retrieval
- CORS headers on preflight and actual requests
- Rate limiting on `/admin/api/auth/login` (>8 requests/minute → 429)
- CSV export via `GET /admin/api/{resource}/export`
- Permission denial (403) for actors without required permissions

**`tests/integration/migrate_integration_test.go`** (`//go:build integration`)
Migration runner against a real PostgreSQL database:
- Ordered execution of SQL files
- Idempotency: running the same migrations twice produces no error and no duplicate work
- Checksum validation: modified migration file after execution → error
- Out-of-order detection: gap in sequence numbers → error
- Partial failure rollback: bad SQL in migration N → database left at N-1

**`tests/integration/cli_integration_test.go`** (`//go:build integration`)
CLI binary (built via `go build`) executed as subprocess:
- `gomyadmin init` — scaffolds complete project structure
- `gomyadmin generate resource` — emits valid Go resource file
- `gomyadmin introspect` — connects to PostgreSQL, outputs valid JSON schema
- `gomyadmin doctor` — runs all checks, returns 0 on healthy environment
- `gomyadmin migrate` — applies SQL files to PostgreSQL
- Unknown command → non-zero exit code with usage output

### CI addition
`go test -tags integration ./tests/integration/...` added as a separate CI step after the existing `go test ./...` step. Runs only when `DATABASE_URL` is set (already configured in CI via the PostgreSQL service added in v0.4).

## Phase 2: Unit Coverage Fill

Target: **≥90%** for every package. Current gaps and what is missing:

### `pkg/migrate` (22% → 90%+)

Missing coverage:
- `Migrate()` with zero migration files
- `Migrate()` with already-applied migrations (idempotency via checksum table)
- `Migrate()` with a file whose checksum changed after first run → error
- `Migrate()` with out-of-order file numbers → error
- `Migrate()` with invalid SQL → error propagation
- `parseVersion()` edge cases: no leading zeros, gaps, non-numeric names

### `pkg/server` (31% → 90%+)

Missing coverage:
- `handleUploadFile` — valid multipart upload, oversized file (>10MB), missing `file` field
- `handleFile` — download by ID, missing file → 404
- `handleFiles` — list files for tenant vs super_admin
- `handleAction` — registered ActionHandler dispatch, unregistered action fallback
- `handleBulkAction` — permission check, response format
- CORS middleware — preflight OPTIONS, allowed origin, disallowed origin
- `requestTimeout` middleware — request that exceeds 10s timeout
- `corsMiddleware` — public URL configuration
- `New()` error paths — both DatabaseURL and Pool supplied → error, missing Store/DatabaseURL/Pool → error

### `internal/cli` (32% → 90%+)

Missing coverage:
- `init` command: valid project name, missing `--module` flag (uses default), `--force` flag
- `generate resource` command: from template, `--force` overwrite
- `generate from-schema` command: valid schema JSON input
- `introspect` command: `--format json`, missing `DATABASE_URL` → error
- `serve` command: starts server, `--port` flag
- `dev` / `build` commands: delegate to docker compose
- `doctor` command: output format, exit code on failure
- `migrate` command: applies files, `--dir` flag
- `version` command: outputs version string

### `internal/introspect` (42% → 90%+)

Missing coverage:
- `ColumnToFieldType` for all supported PostgreSQL types: `uuid`, `jsonb`, `numeric`, `bytea`, `inet`, `text[]`
- `SuggestFieldType` heuristics: email column names, password column names, URL columns
- `IsLikelyPrimaryKey` for compound names (`record_id`, `entry_id`)
- NULL vs NOT NULL column handling
- Columns with default values

### `pkg/audit` (24% → 90%+)

All PostgreSQL store tests currently skip when `DATABASE_URL` is not set. In CI, `DATABASE_URL` is now available — existing skipped tests will run. If coverage still falls short of 90% after enabling them, add unit tests for `MemoryStore` filter combinations (by actor, tenant, resource, date range) to fill the gap.

### Packages already ≥60% — top up to 90%

| Package | Current | Gap |
|---------|---------|-----|
| `pkg/tenant` | 50% | `StaticResolver`, error paths in `ActorResolver` |
| `pkg/postgres` | 64% | `Connect()` with bad URL, pool config options |
| `pkg/pagination` | 65% | `ParsePerPage` with boundary values (0, 101, negative) |

## Phase 3: Bug Fix & Refactor

Triggered by findings from Phases 1 and 2. Known issues to fix regardless:

### `newID()` in `pkg/adapters/sqlstore` — collision-prone
**Problem:** Uses `time.Now().UnixNano()` — collides under rapid creation (exposed by our tests in v0.4).
**Fix:** Replace with `crypto/rand` hex string (8 bytes = 16 hex chars).
```go
func newID() string {
    b := make([]byte, 8)
    _, _ = rand.Read(b)
    return hex.EncodeToString(b)
}
```
**Breaking change:** ID format changes. Document in CHANGELOG.

### `pkg/server/handler.go` — file too large (450+ lines)
**Problem:** Single file handles auth, CRUD, files, actions, audit — hard to navigate and test.
**Fix:** Split into focused files (no logic changes, only file reorganization):
- `handler_auth.go` — login, logout, me
- `handler_crud.go` — list, get, create, update, delete, bulk-delete, export
- `handler_files.go` — upload, download, list files
- `handler_actions.go` — action, bulk-action
- `handler_audit.go` — audit log

### `pkg/migrate` — opaque error messages
**Problem:** Errors like `"migration failed"` without file name or line context.
**Fix:** Wrap errors with file name: `fmt.Errorf("migration %s: %w", filename, err)`.

### API cleanups (breaking, pre-v1.0)
During Phase 2, if any public interface has a design problem that would require a breaking change at v1.0, fix it now. Document each change in CHANGELOG under `### Breaking Changes`.

## Error Handling Policy

| Situation | Action |
|-----------|--------|
| Simple fix | Fix inline, add test, commit |
| Breaking change needed | Fix, update CHANGELOG `### Breaking Changes`, commit |
| Complex fix out of scope | `// TODO(v0.6): <reason>` comment + GitHub issue |
| Test is hard to write | Signals design problem → refactor first, then test |

☐ newID() uses crypto/rand

## CI After v0.5

Add minimum coverage enforcement to `.github/workflows/ci.yml`:
```yaml
- name: Check coverage
  run: |
    go test ./... -coverprofile=coverage.out
    go tool cover -func=coverage.out | awk '/total:/ {if ($3+0 < 90) exit 1}'
```

This prevents coverage regression in future PRs.
